# Saheli — project brief

We're building Saheli, a women's wellness web app, in this folder during a 3-hour hackathon.

# Product
Saheli ("female friend" in Hindi) is an AI companion that reads a woman's cycle and life stage and adapts her food, movement, mind and health care to how her body feels today. Tagline (always under the logo): "Made for every version of her by her". Founder: Neha Racharla, Founder (Certified Nutritionist and Fitness Coach, specialised in women's nutrition; M.S. Artificial Intelligence, Santa Clara University, Silicon Valley). Global, not India-only, but Indian food and culture are first-class.

# Tech
- Next.js (App Router, src/), React, TypeScript, Tailwind CSS, lucide-react icons, vitest for unit tests.
- State: zustand with persist to localStorage, one store per profile (family profiles on one phone). All health data stays on her device. No accounts. Report files and progress photos go in IndexedDB.
- AI is REAL and must work end to end (production, not mocked): @anthropic-ai/sdk in server API routes only. Key in ANTHROPIC_API_KEY (from the Claude Console) in .env.local and in Vercel environment variables; never sent to the browser, never committed (.env* in .gitignore). Model: claude-sonnet-5-5 for chat, report reading and plate photos. Every route: validates input, has a 30s timeout, retries once on 429/529, returns friendly JSON errors, and a GET that says whether AI is configured so the UI can show a kind "not switched on yet" message instead of crashing.
- AI features: (1) Bestie chat, streamed, with her cycle day, phase, mood, symptoms and latest report values as context; (2) report reading: PDF (document block) or photo (image block; resize on the client to max 2000px JPEG; refuse PDFs over 3MB because of Vercel's 4.5MB body limit), forced tool call returns each value converted to our units, test date, lab name and other results, she confirms before saving; (3) Snap your plate: meal photo -> foods and portions matched to our food list, she confirms; (4) Read replies aloud with the phone's speechSynthesis (optional: a loved one's voice through ElevenLabs if ELEVENLABS_API_KEY and ELEVENLABS_VOICE_ID are set).
- Food search: a built-in list of about 150 foods, plus an /api/foods/search route to the USDA FoodData Central API (USDA_API_KEY, falls back to DEMO_KEY).
- Small server store: Upstash Redis from the Vercel Marketplace (KV_REST_API_URL / KV_REST_API_TOKEN, free tier) for four things, each keyed by a random token with a secret to update or delete: Circle links, encrypted cloud backups (the server only ever sees ciphertext), coach requests and plans, and Recommend suggestions. If it isn't configured: Circle falls back to a self-contained link (payload base64 in the URL hash) and the others show "not switched on yet".
- PWA: web manifest, app icons, an "Add to home screen" card, and a service worker (public/sw.js) for offline mode and reminder notifications.
- Voice input: the browser's SpeechRecognition (en-IN, hi-IN, mr-IN).
- Deploy target: Vercel. Must build with `npm run build` and lint clean.
- Working rules for every build prompt: (1) before building a page, open its screenshots in design-reference/ yourself (desktop-NN-*.png and mobile-NN-*.png; each prompt lists the numbers) and match them exactly; (2) when the prompt is done, run the tests, build and lint, fix any errors, then git add, commit with a clear message and git push (once the GitHub remote exists), without waiting to be asked; if another tab holds the git lock, wait a few seconds and retry; (3) never ask me to drag in files or type follow-up commands; only stop to ask when something truly needs me.
- Mobile-first: works at 390px wide with no horizontal scroll. Desktop: left sidebar. Mobile: top bar (logo, Get help pill, profile) and bottom bar (Today, Cycle, Nourish, Companion, More).

# Safety rules (always)
- Saheli guides, never diagnoses. Health screens end with "Saheli explains, it doesn't diagnose. Talk to your doctor." Contraception and screenings say "Saheli explains, it doesn't prescribe." The pain diary flag and PMDD check say "a flag, not a diagnosis".
- Never give calorie targets below BMR. If she's pregnant, breastfeeding, has a medical condition or eating concerns, don't show automatic targets: say "Your coach will set your plan personally."
- If she ticks eating concerns, never show weight numbers or body measurements. Weight tracking is also hidden for the first-period stage (girls) and in pregnancy (which has its own weight-gain log).
- Red-flag symptoms always say "call your doctor" clearly. Very low or very high sugar, a positive pregnancy warning sign, a baby with few wet nappies, thoughts of self-harm: show what to do now and helplines for her country.
- Get help only opens her phone's dialler, WhatsApp or SMS. Nothing is ever sent automatically, and her location is never stored.
- Circle never shares logs, moods, scores, food, journal, chats or intimate symptoms (vaginal dryness, sex, discharge).
- Use only made-up sample data. No real personal or health information.
